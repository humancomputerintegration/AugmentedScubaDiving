이 프로젝트는 사용자가 다시 제공한 **HCI_Project2_Team-15-main(2).zip**에 승인한 변경만 적용한 전체 프로젝트입니다. Unity 버전은 **6000.3.27f2**입니다.

## 1. 새 폴더에서 열기

1. ZIP을 완전히 압축 해제합니다.
2. Unity Hub에서 **Add → Add project from disk**를 선택합니다.
3. `Assets`, `Packages`, `ProjectSettings`가 바로 들어 있는 **HCI_Team15_Final** 폴더를 고릅니다.
4. Editor는 **6000.3.27f2**로 엽니다.
5. 패키지 복원과 가져오기가 끝나면 `Assets/Diving Simulation/Scenes/Simulation.unity`를 엽니다.
6. **HCI → Validate Hands Demo**를 실행하고 Console을 확인합니다. 이 기존 메뉴는 연결을 검사합니다.
7. PC에서는 키보드·마우스로 화면과 통화를 확인합니다. Quest 손 입력은 Android 빌드에서 확인합니다.
8. **File → Build Profiles → Android → Build and Run**으로 설치합니다. 사용 중인 PC의 Android SDK/NDK/JDK와 Quest 연결 상태는 그대로 사용합니다.

이번 전달물은 전체 프로젝트입니다. 다른 ZIP이나 누적 패치를 추가로 덮어쓸 필요가 없습니다.

## 4. 코드를 처음 읽을 때

### CircleGraphic.cs: 입력 버튼과 눈에 보이는 그림은 다릅니다

`Button`은 눌렀을 때 무엇을 실행할지 알고 있습니다. `CircleGraphic`은 그 버튼의 원 모양과 색을 그립니다. 이번에는 그리는 부분을 바꿨습니다.

- `roundness`가 0이면 기존 단색 원을 그립니다. 선택 강조용 원도 이 경로를 그대로 씁니다.
- 실제 메뉴 버튼 11개에는 `roundness = 0.55`를 저장했습니다. 숫자가 클수록 명암 차이가 커집니다.
- 원을 네 겹으로 나누어, 가운데와 위쪽은 조금 밝게, 아래쪽과 가장자리는 조금 어둡게 그립니다.
- 점의 z 좌표를 튀어나오게 하지 않으므로 실제 버튼 표면이나 손의 판정 위치가 바뀌지 않습니다.
- `phoneIcon`이 켜진 원에는 수화기 모양을 추가합니다. 이모지 글꼴이 없어도 도형은 존재합니다.

`float`는 0.55 같은 소수, `Color`는 빨강·초록·파랑·불투명도의 네 값, `Vector2`는 가로·세로 좌표입니다. `for`는 같은 계산을 여러 점에 반복합니다. 이 파일의 각 의미 있는 코드 줄 옆에 구체적인 설명을 붙였습니다.

### SoftButtonFeedback.cs: 한 번 클릭하면 그림만 움직입니다

이 컴포넌트는 기존 `Button.onClick` 알림을 듣습니다. 손 입력 담당자가 원래 버튼을 실행하면, 이 컴포넌트는 눌린 모습을 잠깐 보여 줍니다.

1. `Awake`에서 버튼, 그림, 아이콘의 원래 위치를 준비합니다.
2. `OnEnable`에서 클릭 알림을 등록합니다.
3. 클릭하면 경과 시간을 0으로 시작합니다.
4. `Update`에서 0.07초 동안 눌리고, 다음 0.14초 동안 돌아오는 정도를 계산합니다.
5. `OnDisable`에서 알림을 해제하고 원래 모습으로 돌립니다. 메뉴를 다시 열 때 중복 알림이 쌓이지 않습니다.

예를 들어 얼굴 반지름이 43이면, 아이콘이 가장 많이 내려가는 양은 `43 × 0.018 = 0.774` UI 단위입니다. 버튼 루트와 Collider는 움직이지 않습니다. 이 컴포넌트가 통화를 다시 걸거나 메뉴 열기 함수를 한 번 더 호출하는 일도 없습니다.

### HandUIAnchor.cs: 위치 선택 하나만 추가했습니다

기존 위치 번호는 Forearm=0, Wrist=1, BackOfHand=2입니다. 여기에 Palm=3을 뒤에 추가했습니다. 기존 번호를 바꾸면 Scene에 저장된 0과 1이 다른 의미가 될 수 있으므로 순서를 보존했습니다.

손바닥 안내일 때만 다음을 계산합니다.

```text
안내 위치 = 손바닥 위치 + 시야 위쪽 × 0.10m + 눈을 향하는 방향 × 0.03m
```

`head.up`은 현재 시야에서 위쪽 방향입니다. `normalized`는 방향을 유지하면서 벡터의 길이를 1로 만드는 값입니다. 여기에 0.03을 곱하면 거리가 항상 3cm가 됩니다. 기존 왼팔·손목 UI는 원래 식을 계속 사용합니다.

### SimpleDial.cs: 재생 명령과 실제 출력 작업을 구분합니다

`AudioSource.Play`는 음원을 재생하라는 명령입니다. Android에서 소리를 실제로 내보내는 작업이 멈춰 있다면, 재생 상태만 보는 것으로는 충분하지 않을 수 있습니다.

추가한 `EnsureMobileAudioOutput`은 다음 순서만 실행합니다.

1. 실제 Android 기기 빌드인지 구분합니다. PC Editor에는 Android 복구 코드를 넣지 않습니다.
2. 앱이나 전체 오디오가 일시정지 중이면 복구를 시도하지 않습니다.
3. `AudioSettings.Mobile.audioOutputStarted`가 true이면 이미 실행 중이므로 끝냅니다.
4. false일 때만 `StartAudioOutput()`을 요청합니다.

앱 복귀 때도 같은 검사를 합니다. 시스템 음량·출력 장치·손 추적 설정을 바꾸지 않습니다. 통화 상태 전환, FREQ/PHONE, SOS 우선 처리, 자동 수신 2회 제한은 기존 코드입니다.

이 복구 조건이 이번 헤드셋 무음의 실제 원인이었는지는 아직 기기 로그와 청취로 확인하지 못했습니다. 따라서 파일을 수정했다는 이유만으로 음성 문제가 해결됐다고 표시하지 않습니다.

### DiverMobile.shader: 옷 색을 유지하며 VR 화면에 그립니다

셰이더는 C#과 달리 GPU가 물체의 표면을 그릴 때 쓰는 코드입니다. 잠수부 재질만 이 파일을 직접 참조합니다. 기존 URP 설정이나 물·물고기 재질은 바꾸지 않았습니다.

이 파일은 기본 방향광, 안개, 양쪽 눈의 인스턴스 정보를 처리합니다. 기존 기준본도 유효한 URP/Lit을 참조하고 있었으므로, 이번 변경은 잠수부 렌더링 경로를 분명하게 만드는 보완입니다. **기기에서 분홍색 오류가 사라졌는지는 별도 확인 항목**입니다.

## 6. 이번 APK에서 마지막으로 확인할 순서

이전 기준본에서 통과한 기능을 임의로 다시 설계하지 않았습니다. 다음 항목은 새 APK가 그 동작을 유지하는지와 이번 변경을 확인하는 짧은 순서입니다.

- [ ] 새 프로젝트의 Console에 빨간 오류가 없고 Android Build and Run이 성공한다.
- [ ] 왼손을 모으면 시선 방향으로 이동하고, 펴면 멈춘다.
- [ ] 왼손 스와이프로 메뉴가 열리고 닫히며, 왼팔·오른손목 UI가 보인다.
- [ ] 오른손 포인터로 버튼을 가리킨 뒤 오므렸다 펴면 한 번 선택된다. 가까이 직접 누르기도 된다.
- [ ] 버튼 5종의 색이 구분되고, 손전등까지 약한 볼륨과 눌림 느낌이 보인다.
- [ ] 양손 안내가 손 위에서 읽히며, 잠수 중 왼손 이동과 오른손 엄지 위·아래가 동시에 된다.
- [ ] 물속에서 DIVE TIME이 표시된 상태에서도 상단 HUD가 지도와 겹치지 않는다.
- [ ] 전화·SOS 팝업의 글자가 배경에 묻히지 않는다.
- [ ] 산호 영역이 넓어졌고 거북이 3마리가 이동한다.
